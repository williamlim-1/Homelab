# Documentation Process

This repository is designed so an infrastructure session can be documented as it happens.

## How To Use It

1. Make the infrastructure change in PVE, OPNsense, or a VM.
2. In the same session, document what changed.
3. Update the journal entry and any relevant public or private docs.
4. If a detail is uncertain, mark it clearly instead of guessing.

## Preferred Outcomes

- Public docs describe what exists and why it exists.
- Journal entries capture the engineering story of the change.
- Private docs hold the exact addresses and operational details.

## When Information Is Missing

Use a short placeholder such as:

- `TBD`
- `Needs Verification`
- `Unknown`
- `Planned`
- `Not Yet Implemented`
